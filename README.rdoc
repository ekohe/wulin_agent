= wulin_agent

Conversational AI agent for Wulin Master apps. Exposes grid CRUD and custom
actions as LLM tools (ruby_llm + MCP), gated by wulin_permits.

== Installation

Host apps vendoring the gem under +vendor/gems/wulin_agent+:

1. Add to your Gemfile:

     gem "wulin_agent", path: "vendor/gems/wulin_agent"

2. Initialize the submodule:

     git submodule update --init --recursive

3. Install dependencies:

     bundle install

== Integration

=== Prerequisites

+wulin_agent+ is a Rails engine for Wulin Master apps. Host apps need:

* +wulin_master+ (required dependency, declared in the gemspec)
* +wulin_permits+ (recommended: LLM tools are gated by grid permissions)
* PostgreSQL (+agent_messages.metadata+ is +jsonb+)

Follow the standard Wulin Master / Wulin Permits setup in your app (migrations,
menus, +rake wulin_permits:load_permissions+ after adding grids).

=== OpenAI

The engine configures +ruby_llm+ at boot. Provide an API key via environment
variable or Rails credentials:

  OPENAI_API_KEY=sk-...

  # config/credentials.yml.enc
  openai:
    access_token: sk-...

+ENV["OPENAI_API_KEY"]+ takes precedence; credentials are used as fallback.

=== Database

The engine appends its migrations to the host app (+agent_conversations+,
+agent_messages+). Run:

  rails db:migrate

+agent_conversations+ references +users+; ensure a +users+ table exists before
migrating.

=== Agent actions

Grid custom actions (declared with +action+ on a +WulinMaster::Grid+) can be
exposed to the LLM as tools alongside CRUD. Use +agent_action+ to describe how
the agent should call them:

  class PersonGrid < WulinMaster::Grid
    action :greet, icon: :waving_hand, title: "Greet"

    agent_action :greet,
      description: "Say hello to someone by name",
      params: { name: { type: :string, required: false } },
      mutating: true
  end

Only actions backed by a controller method are exposed. UI-only actions (e.g.
+:fullscreen+ with no controller endpoint) are ignored. The tool name follows
+<controller>__<action>+ (e.g. +people__greet+) and is gated by
+wulin_permits+ (+people#greet+).

+agent_action+ options:

* +description+ — text shown to the LLM (falls back to the grid action title)
* +params+ — JSON schema for arguments (+type+, +required+). When omitted,
  parameters are inferred from the controller method via AST
* +mutating+ — whether the action requires write approval (+true+/+false+).
  Defaults to HTTP method: custom actions use POST and are treated as mutating

At runtime, +ActionInferer+ builds a +ToolSpec+ that dispatches through
+GridDispatcher+ to the grid controller, with the same permissions as the UI.

== Frontend assets

JavaScript/CSS are built with esbuild under +app/+ and committed to
+app/assets/builds/+ (+wulin_agent.js+, +wulin_agent.css+).

+node_modules/+ is gitignored; run +npm ci+ after clone.

The engine registers these assets for precompile. Host apps must link them in
+app/assets/config/manifest.js+:

  //= link wulin_agent.js
  //= link wulin_agent.css

And require them in the main asset bundles:

  // app/assets/javascripts/application.js
  //= require wulin_agent

  /* app/assets/stylesheets/application.css */
  *= require wulin_agent

== Development

  git submodule update --init --recursive
  cp spec/dummy/config/database.example.yml spec/dummy/config/database.yml
  bundle install
  cd app && npm ci && npm run build
  bundle exec rspec

Wulin gems are vendored as git submodules under +vendor/gems/+ (same layout as
wulintest). +wulin_master+ is a sibling repo on GitLab
(+../wulin_master.git+). CI uses +GIT_SUBMODULE_STRATEGY: recursive+ (same
GitLab instance, no SSH keys required).
